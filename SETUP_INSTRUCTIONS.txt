## ⚡ 30-Second Setup

### Website Server
```bash
# Edit .env and set:
VPS_ENABLED=true
VPS_HOST=your-vps-ip-address
VPS_PORT=5000
VPS_AUTH_TOKEN=generate-random-token-here
VPS_PROTOCOL=http

# Restart:
npm start
```

### VPS Server
```bash
# Copy vps-worker-template.js to ~/voidhaven-bots/
# Create .env with:
VPS_PORT=5000
VPS_AUTH_TOKEN=same-token-as-website

# Install and run:
npm install express discord.js dotenv
node vps-worker-template.js
```

**Done!** Your bots are now hosted on your VPS.

## 🔑 Key Concepts

### VPS_ENABLED
- `true` = Bots run on your VPS (production)
- `false` = Bots only exist in dashboard (testing)

### VPS_HOST
- Your VPS's IP address or domain
- Examples: `192.168.1.100`, `bots.example.com`, `vps.myhosting.com`

### VPS_AUTH_TOKEN
- Shared secret between website and VPS
- Generate with: `openssl rand -base64 32`
- **Must be identical on both sides**

### VPS_PROTOCOL
- `http` for local/testing
- `https` for production (requires SSL certificate)

## 🚀 Workflow After Setup

1. **User signs in** to your website
2. **Enters bot token** and selects modules
3. **Clicks "Host Bot"**
4. Website **stores bot** and **sends to VPS**
5. VPS **spawns Discord bot**
6. **Bot runs 24/7** on your VPS
7. User can **manage** (enable/disable modules) or **delete**
8. User can host **up to 3 bots** per account

## 🔒 Security Notes

- **HTTPS**: Use `VPS_PROTOCOL=https` with SSL cert in production
- **Firewall**: Restrict port 5000 to only your website server's IP
- **Token**: Generate strong random token, never share publicly
- **Privacy**: Bot tokens are never stored on disk, only in memory

## 📞 Common Questions

**Q: Do I need to deploy to a VPS immediately?**
A: No! Set `VPS_ENABLED=false` to test locally first.

**Q: Can I add custom module features?**
A: Yes! Edit the `messageCreate` event in `vps-worker-template.js`.

**Q: What if my bot disconnects?**
A: The worker will automatically log the error. Check VPS logs.

**Q: Can users run their own bot hosting?**
A: Yes, if you distribute the worker template to them.

**Q: Does this support multiple VPS?**
A: Currently it connects to one VPS. Multiple VPS requires custom routing.
